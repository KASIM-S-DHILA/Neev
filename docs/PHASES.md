# Build phases

The user authorized implementation on September 30, 2026. Build one reviewable milestone at a time. The UX Pilot PDF is the visual baseline; functional agreements take precedence over contradictory mockup details (locked topics, mastery inferred from reading, and permanently open support drawers).

“Independently evaluable” means each phase has its own entry point, deterministic fixtures, acceptance criteria, and report. Runtime dependencies may exist, but evaluation must not require an entire live model/provider pipeline. Stubs are permitted only in tests and must be labeled; no mock success in the student UI.

- Workspace > Subject > Topic; each study tab holds its own context.
- Original source records and versioned content units with page/slide/timestamp locators.
- Jobs with queued/running/partial/succeeded/failed/cancelled states, checkpoints, and bounded retries. A succeeded integrity job does not mean content is ready for retrieval.
- Assessments with verified answer keys, scope, confidence and grading states; faulty questions can be voided/regraded.
- Evidence events with stable IDs and rollback, so learner estimators do not count the same observation as independent votes.
- Explicit external-search permission and import records.

## Non-negotiable resource rules

Target 8 GB RAM, a decent CPU, and optional low-VRAM GPU. Heavy extraction/inference runs outside the Electron renderer and main event loop. Only one heavy local worker/model is active at a time by default. Virtualize large lists, render document pages on demand, release model/preview resources when not used, and retain resumable progress. Measure resource use; do not promise latency before benchmarking.

## Learner methods in Phase 12a/12b

All are required: Bayesian knowledge tracing; IRT-style ability/difficulty estimation; Performance Factors Analysis; prerequisite tracking; step/misconception evidence; confidence calibration; spaced repetition; active recall; interleaved practice. Keep them behind simple evidence-based student statuses and explainable recommendations. Conversation evidence is qualified by assistance; reading, skipping, timing out or missing a schedule block must not automatically count as incorrect independent assessment evidence.

## Evaluation process

Every phase documents setup, fixture provenance, expected results, automated/manual commands, results, limitations, and remaining risks. A phase is complete only when its gate passes or a concrete limitation is explicitly recorded. Create the gold source-location fixtures during ingestion, not at the end. Actual RAGAS quality and personalization gains require measured runs; passing UI/unit tests is not evidence of learning effectiveness.

Live audio tutoring and speech-model selection remain on hold. Audio source ingestion and generated audio briefs remain in scope.
